# Как помочь {#how-to-help}

Warpnet — свободное ПО с открытым кодом, и помогает каждый отчет об ошибке, relay-узел, pull request или перевод. На этой странице перечислены способы помочь — от тех, что не требуют технических навыков, до тех, где нужен компилятор.

## С чего начать {#start-here}

- **Пользователям:** установите Warpnet с [warpnet.site/download](https://warpnet.site/download), как описано в [руководстве пользователя](user-guide/index.md), и попробуйте его в testnet.
- **Разработчикам:** прочитайте [руководство разработчика](developer-guide/index.md).
- **Всем:** [чат разработчиков в Telegram](https://t.me/warpnetdev) — самый быстрый способ задать вопрос или найти подходящую задачу.

## Тестирование в testnet {#test-on-testnet}

Testnet — отдельная сеть для экспериментов. У нее свой сетевой ключ, поэтому ничто из того, что вы там делаете, не попадает в mainnet.

- **Компьютер.** При первом запуске на экране регистрации есть переключатель **Network**. Из терминала команда `warpnet --node.network testnet` сразу запускает приложение в testnet.
- **Телефон.** Установите [warpdroid из F-Droid](https://f-droid.org/packages/site.warpnet.warpdroid/) (Android 7.0 или новее) или [Warpnet из App Store](https://apps.apple.com/app/warpnet/id6835178022) (iOS 17 или новее) и подключите его к узлу в testnet: сеть берется из QR-кода. См. [Мобильные приложения](user-guide/mobile.md).
- **Несколько узлов.** Запустите десктопный узел и [удаленный узел](user-guide/running-a-node.md#remote-node) на двух машинах в своей локальной сети или VPN с двумя аккаунтами. Подпишитесь одним аккаунтом на другой, напишите в чат, поставьте реакцию и проверьте, что доходит до другой стороны.
- **С чистого листа.** Данные testnet хранятся в `~/.warpdata/testnet/` (в Windows — `%LOCALAPPDATA%\warpdata\testnet\`). Удалите эту папку или выполните `make prune-testnet` в каталоге с исходниками, и вы начнете заново.

Пользуйтесь интерфейсом, пытайтесь его сломать и сообщайте о том, что произошло.

## Сообщения об ошибках {#report-bugs}

Создайте issue на [github.com/Warp-net/warpnet/issues](https://github.com/Warp-net/warpnet/issues). Полезный отчет содержит:

| Пункт | Где взять |
|---|---|
| Версия | выводится в первой строке при запуске узла и показывается в панели информации об узле на главном экране (Home) |
| Клиент | десктоп, браузерная панель управления (удаленный узел), Android или iOS |
| Операционная система | и способ установки (загрузка с warpnet.site, Snap, F-Droid, App Store, из исходников) |
| Сеть | `warpnet` (mainnet), `testnet` или ваша собственная |
| Шаги | что вы делали, чего ожидали, что произошло |
| Логи | запустите узел с `LOGGING_LEVEL=debug` и приложите нужный фрагмент |

Перед публикацией уберите из логов все личное. Если ошибка связана с безопасностью, не создавайте публичный issue, а напишите на contact@warpnet.site.

## Запуск relay-узла {#run-a-relay-node}

Relay-узел — это узел без графического интерфейса и без аккаунта. Свое состояние он держит в памяти и не хранит пользовательских данных. Он участвует в DHT, через которую узлы находят друг друга, передает дальше объявления обнаружения, жалобы и голоса модераторов и пересылает зашифрованный трафик (circuit relay v2) для узлов за NAT. Запущенный вами relay-узел подключается к сети через встроенные bootstrap-узлы, но узлы за NAT пускают свой трафик только через узлы из собственного bootstrap-списка. Поэтому ваш relay-узел пересылает трафик для тех member-узлов, которые добавили его адрес в свой bootstrap-список, и каждый из них меньше зависит от bootstrap-узлов проекта. См. [Relay-узлы и bootstrap-узлы](user-guide/running-a-node.md#relay-and-bootstrap-nodes).

Что нужно:

- машина с публичным IP-адресом и стабильным подключением; бинарный файл из релиза и Docker-образ предназначены для Linux x86-64, а на других платформах, кроме Windows, relay-узел можно собрать из исходников;
- открытый TCP-порт 4001 (или порт, выбранный через `--node.port`) для IPv4 и, если есть, для IPv6.

**Из релиза.** Скачайте `relay_linux_amd64.tar.gz` из [последнего релиза](https://github.com/Warp-net/warpnet/releases/latest), сверьте его с `relay_linux_amd64_checksums.txt` и его `.sig` ([Проверка загрузки](user-guide/index.md#verify-the-download)), распакуйте и запустите:

```bash
NODE_SEED="<a long random string>" ./relay
```

**В Docker.** CI собирает образ `ghcr.io/warp-net/warpnet-relay` из `Dockerfile.relay`.

```bash
docker run -d --name warpnet-relay --network host --restart unless-stopped \
  -e NODE_SEED="<a long random string>" \
  ghcr.io/warp-net/warpnet-relay:latest
```

Образ можно собрать и самостоятельно из `Dockerfile.relay` в репозитории.

> **Примечание:** peer ID relay-узла выводится из `--node.seed`. Без него seed вычисляется из имени сети, каталога базы данных, адреса привязки и порта, а их может воспроизвести кто угодно. Задайте длинный случайный `NODE_SEED` и сохраните его: так ваш relay-узел сохранит ту же идентичность между перезапусками, а никто другой не сможет вычислить его ключ.
{: .note }

По умолчанию relay-узел работает в mainnet (добавьте `--node.network testnet`, чтобы вместо этого помогать testnet), а на Linux x86-64 сам обновляется из подписанных релизов на GitHub, если не передать `--node.self-update=false`. При запуске он выводит свой peer ID и адреса; передайте member-узлам полный адрес, как описано в разделе [Ваш relay-узел как bootstrap-узел](user-guide/running-a-node.md#use-your-relay-as-a-bootstrap-node). Внутреннее устройство описано на странице [Архитектура relay-узла](relay-node-architecture.md).

## Запуск узла-модератора {#run-a-moderator-node}

Узлы-модераторы оценивают контент, на который пожаловались, с помощью небольшой языковой модели, работающей локально. Запустить такой узел может любой: не нужно ни подавать заявку, ни получать одобрение, но и особых полномочий вы не получите. Ваш голос весит столько же, сколько голос любого другого модератора, и выбирать, какие жалобы рассматривать, нельзя. Ваша машина будет загружать контент, на который пожаловались, и оценивать его, отвечать на выборочные проверки от других модераторов и подписывать свои голоса ключом узла. Как устроен процесс, описано на странице [Модерация](moderation.md).

Что нужно:

- машина с Linux x86-64, где хватает памяти и CPU для модели на 1B параметров, и стабильное подключение;
- файл модели `Llama-Guard-3-1B-Q4_K_M.gguf` в каталоге, из которого запускается модератор. Имя файла зашито в код, а сама модель с Warpnet не поставляется;
- либо архив релиза `moderator_linux_amd64.tar.gz` (собран на Ubuntu 24.04 и динамически слинкован с glibc, libstdc++ и libgomp), либо Docker с `Dockerfile.moderator` из репозитория. Как смонтировать файл модели в контейнер, показано в `deploy/docker-compose-moderator.yml`.

Настройки модератора описаны в разделе [Узел-модератор](user-guide/running-a-node.md#moderator-node), а как собрать и запустить его из исходников в testnet — в разделе [Модератор](developer-guide/index.md#moderator) руководства разработчика.

## Написание кода {#write-code}

Сначала прочитайте [руководство разработчика](developer-guide/index.md): там описаны сборка каждой роли, структура проекта и подробный пример добавления маршрута. Затем выберите issue с меткой [`good first issue`](https://github.com/Warp-net/warpnet/labels/good%20first%20issue) или [`help wanted`](https://github.com/Warp-net/warpnet/labels/help%20wanted).

Где помощь нужнее всего:

| Область | Где | Навыки |
|---|---|---|
| Десктопный и браузерный интерфейс | `frontend/` | Vue 3, JavaScript, Tailwind |
| Приложение для Android | `warpdroid/` | Kotlin |
| Приложение для iOS | `warpfone/` | Swift, SwiftUI |
| Проверка контракта между клиентами и узлом | `frontend/src/service/service.js` и `warpdroid/warpnet-transport/…/ProtocolIds.kt` в сравнении с `event/paths.go` | скрипты, CI; список маршрутов iOS генерирует `warpfone/scripts/generate-protocol-ids.sh`, и CI его проверяет, а десктопный и Android-списки синхронизируются вручную |
| Обход NAT и связность | `core/relay`, `core/holepunch`, `core/discovery` | libp2p, сети |
| Тесты и CI | везде | тестирование на Go |
| Сообщения об ошибках и справка CLI | `config/`, обработчики | умение понятно писать |

Коротко о процессе: сделайте форк, создайте ветку от `develop`, добавьте в новые файлы Go такой же заголовок AGPL, как в существующих, выполните `make tests` и `golangci-lint run` и откройте pull request в `develop`. CI запускает `golangci-lint` и `go test -race` для каждого pull request. Вклад регулируется [Лицензионным соглашением участника](legal/CLA.md). Открывая pull request, вы с ним соглашаетесь, подписывать ничего не нужно.

## Исследования и ревью {#research-and-review}

- Проверьте криптографию: транспорт Noise, сетевой ключ (PSK), ключи идентичности и базы данных, которые выводятся из логина и пароля, канал Noise удаленной панели управления и подпись релизов. Начните со страницы [Безопасность](security.md).
- Предлагайте улучшения [модерации](moderation.md), [обнаружения пиров](discovery.md) и [рейтинга узлов](rating.md).

## Переводы и документация {#translate-and-document}

- **Описание в каталоге приложений.** Описание для F-Droid в `fastlane/metadata/android/` есть только на `en-US`. Добавить язык — небольшой самостоятельный первый вклад.
- **Интерфейс десктопного приложения.** В приложении на Vue пока нет слоя переводов. Если его добавить, интерфейс можно будет перевести на другие языки.
- **Эта документация.** Документация лежит в репозитории [Warp-net/docs](https://github.com/Warp-net/docs). Исправления, переводы и руководства принимаются в виде pull request.
