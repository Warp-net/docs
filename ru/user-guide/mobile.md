# Мобильные приложения {#mobile-apps}

У Warpnet есть приложение для Android и приложение для iOS. Оба — компаньоны: они читают и публикуют от вашего имени через узел, который у вас уже работает, на компьютере или на сервере. На этой странице описано, как их установить, как работает сопряжение, как отключить телефон и какие функции доступны на телефоне.

## Зачем телефону узел {#why-a-phone-needs-a-node}

Телефон плохо подходит на роль узла пиринговой сети: система приостанавливает фоновые приложения, радиомодуль засыпает, а IP-адрес постоянно меняется. Поэтому аккаунт хранится не на телефоне. Он живет на **узле** (в десктопном приложении или на [удаленном узле](running-a-node.md#remote-node)), который остается в сети, хранит ваши данные и поддерживает сетевые соединения. Телефон подключается к этому узлу и работает через него.

Отсюда следует:

- Аккаунт создается в десктопном приложении или на удаленном узле, а не на телефоне.
- Чтобы телефон работал, узел должен быть запущен, и в нем должен быть выполнен вход. Выход из десктопного приложения останавливает узел; если нужно только скрыть окно, используйте блокировку экрана.
- Пока подключен хотя бы один телефон, узел просит операционную систему не переходить в спящий режим (экран при этом может гаснуть и блокироваться).

## Установка {#install}

| | Android | iOS |
|---|---|---|
| Приложение | Warpnet (`site.warpnet.warpdroid`) | Warpnet (`site.warpnet.warpfone`) |
| Где взять | [F-Droid](https://f-droid.org/packages/site.warpnet.warpdroid/) или `warpdroid.apk` из [релиза на GitHub](https://github.com/Warp-net/warpnet/releases/latest) | [App Store](https://apps.apple.com/app/warpnet/id6835178022) |
| Требования | Android 7.0 или новее, 64-битный ARM (`arm64-v8a`) | iOS 17 или новее |
| Основано на | [Tusky](https://github.com/tuskyapp/Tusky) (клиент Mastodon, Kotlin) | Ice Cubes 1.10.31 (клиент Mastodon, SwiftUI) |
| Исходный код | [`warpdroid/`](https://github.com/Warp-net/warpnet/tree/main/warpdroid) | [`warpfone/`](https://github.com/Warp-net/warpnet/tree/main/warpfone) |

Версия в F-Droid может отставать от релиза на GitHub на несколько версий. APK на GitHub собирается по тому же рецепту, что и в F-Droid, и подписан ключом проекта; SHA-256 отпечаток его сертификата — `eabdd61e5bcbd6615a3f54977c06646c0f5422d845d37c818286b7d34285dfec`. Рядом с ним публикуются файл `warpdroid_checksums.txt` и его подпись `.sig` (см. [Проверка загрузки](index.md#verify-the-download)).

У приложения для Android нет зависимостей от Google Play Services, Firebase и других проприетарных компонентов. Уведомления приходят по его собственному соединению с вашим узлом, а не через push-сервис.

Оба приложения содержат тот же сетевой код на Go, что и десктопный узел. Он скомпилирован прямо в приложение, поэтому приложения работают с протоколом напрямую, а не через сервер.

## Сопряжение телефона {#pair-a-phone}

1. На компьютере войдите в Warpnet. Откройте меню аккаунта и выберите **Sign in by QR-code** (вход по QR-коду). Появится QR-код.
2. Откройте приложение Warpnet на телефоне. При первом запуске оно открывает сканер QR-кодов.
3. Наведите камеру на код. Приложение покажет узел, его владельца и адрес и попросит подтвердить. Приложение для iOS также показывает правила публикации контента и поведения: включите **I agree**.
4. Нажмите **Connect**. Телефон соединится с вашим узлом и выполнит сопряжение.

Нет камеры или компьютер далеко? Под QR-кодом нажмите **Copy connection data**. На телефоне выберите **Enter pairing data manually**, вставьте данные и нажмите **Pair**. Передавайте их на телефон только по каналу, которому доверяете: любой, у кого есть эти данные, может подключить устройство к вашему узлу.

### Что содержит QR-код {#what-the-qr-code-contains}

В QR-коде записаны данные для сопряжения с вашим узлом. Они сжаты gzip и закодированы в Base45, чтобы поместиться в QR-код:

| Поле | Назначение |
|---|---|
| `token` | Токен сопряжения, выданный работающим узлом. Узел принимает сопряжение только с текущим токеном. |
| `psk` | Сетевой ключ, чтобы телефон подключился к нужной сети. |
| `node_id` | peer ID вашего узла. Телефон проверяет его во время зашифрованного рукопожатия и отказывается от сопряжения, если узел по этому адресу — другой пир. |
| `addresses` | Где найти ваш узел (локальные и публичные адреса). |
| `bootstrap_peers` | Relay-узлы, которые использует ваш узел, чтобы телефон мог выйти в сеть. |
| `network`, `user_id` | К какой сети и к какому аккаунту подключается телефон. |

QR-код никогда не содержит ваш приватный ключ или пароль. Телефон создает собственный ключ, по одному на каждый узел, с которым он сопрягается, поэтому при повторном сопряжении с тем же узлом у телефона остается прежний ключ. Каждый запрос с телефона подписывается этим ключом, а узел принимает приватные запросы только от ключей, которые он записал как подключенные устройства.

### Как телефон связывается с узлом {#how-the-phone-reaches-your-node}

Приложение сначала пробует адрес вашего узла в локальной сети, затем его публичный адрес (публичный IP, проброс порта или отображение UPnP / NAT-PMP, которое узел настраивает на вашем роутере). Если ни то ни другое не работает, соединение идет через один из relay-узлов. Relay-узел пересылает трафик, который не может прочитать: шифрование Noise работает сквозным образом между телефоном и вашим узлом. Подробнее — на странице [Сеть и транспорт](../network.md).

Значок монитора на верхней панели приложения показывает состояние связи:

- **Зеленый**: есть связь с вашим узлом, напрямую или через relay-узел.
- **Красный**: узел недоступен (приложение закрыто, компьютер офлайн или спит, или нет сети). Телефон продолжает попытки.

### На Android {#on-android}

Некоторые производители Android-устройств агрессивно останавливают фоновые приложения, и из-за этого перестают приходить уведомления. В приложении есть экран **Keep Warpnet running** с настройками, которые нужно изменить на вашем устройстве (оптимизация батареи, а на Huawei и Xiaomi — еще и параметры производителя).

## Управление подключенными устройствами {#manage-paired-devices}

На компьютере в **Settings → Devices** перечислены подключенные телефоны с платформой, peer ID и временем последней активности.

| Правило | Значение |
|---|---|
| Сколько устройств можно подключить одновременно | до 10 |
| Устройство, которое перестало выходить на связь, удаляется через | 3 дня |
| Удаление устройства | действует сразу |

Кнопка **Remove** в **Settings → Devices** немедленно отзывает доступ телефона. С оставшимися у него данными он заново подключиться не сможет; если отсканировать новый QR-код с вашего узла, телефон подключится как новое устройство. Поэтому потеря телефона — проблема с ограниченными последствиями: удалите его, а ключей вашего аккаунта на нем никогда не было.

С телефона:

- iOS: **Settings → Unpair this device** удаляет телефон из вашего узла и забывает сопряжение.
- Android: **Forget paired node** удаляет сопряжение на телефоне. Узел продолжает показывать телефон в списке, пока вы не удалите его в **Settings → Devices** или пока не пройдут 3 дня.

> **Примечание:** Токен сопряжения хранится в памяти узла и меняется при каждом перезапуске процесса узла (когда десктопное приложение закрывают и открывают снова или когда перезагружается компьютер). Если телефон выходит на связь со старым токеном, узел отвечает, что сопряжение больше не принимается, и телефон просит отсканировать код заново. Откройте **Sign in by QR-code** на компьютере и отсканируйте новый код.

## Что работает на телефоне {#what-works-on-a-phone}

Оба приложения покрывают повседневные функции соцсети. Администрирование узла остается на компьютере.

| Функция | Android | iOS | Компьютер |
|---|:---:|:---:|:---:|
| Главная лента, треды, профили | да | да | да |
| Публикация, ответ, редактирование, удаление; изображения и видео | да | да | да |
| Ретвиты, цитаты, реакции эмодзи, голосование в опросах, закрепление, закладки | да | да | да |
| Подписка, отписка, ответ на запросы на подписку | да | да | да |
| Одобрение новых подписчиков (закрытый аккаунт) | да | нет | нет |
| Личные сообщения | да | да | да |
| Изображения и видео в личных сообщениях | да | нет | да |
| Уведомления | да | да | да |
| Блокировки, игнорирование, фильтры по ключевым словам | да | да | да |
| Жалоба на пост или профиль | да | да | да |
| Создание аккаунта, вход, выход | нет | нет | да |
| Сопряжение и удаление устройств | нет | нет | да |
| Импорт постов из X | нет | нет | да |
| Кошелек и спонсорские посты | нет | нет | да (testnet) |
| Рейтинг узла, сеть, ограничение частоты запросов, шлюз моста, настройки e-mail | нет | нет | да |
| Блокировка экрана (PIN) | нет | нет | да |
| Предложения обновиться | нет | нет | да |

Таблица составлена по маршрутам протокола, которые реализует каждое приложение ([`ProtocolIds.kt`](https://github.com/Warp-net/warpnet/blob/main/warpdroid/warpnet-transport/src/main/kotlin/site/warpnet/transport/ProtocolIds.kt) для Android, маршрутизатор в [`warpfone/Packages/Network`](https://github.com/Warp-net/warpnet/tree/main/warpfone/Packages/Network) для iOS). Из приложения для iOS удалены экраны функций Mastodon, которых нет в узле.

## Приватность на телефоне {#privacy-on-the-phone}

- Телефон хранит собственный ключ и данные сопряжения. Ваш пароль и приватный ключ узла на нем не хранятся.
- Что телефон отправляет relay-узлам: свой peer ID и публичный ключ, user agent `warpdroid` (Android) и запросы маршрутизации DHT. Relay-узлы видят ваш IP-адрес, но не ваши посты и сообщения.
- Чтобы relay-узлы проекта не участвовали в соединении, запустите собственный relay-узел и запускайте свой узел с `--node.bootstrap`: телефон использует тот список relay-узлов, который передает ему ваш узел. См. [Запуск узла](running-a-node.md#relay-node).
- Соединения обернуты в слой TLS, который имитирует браузер, обращающийся к `www.googleapis.com`, поэтому сетевые мониторы вроде PCAPdroid показывают это имя рядом с адресом вашего узла или relay-узла. В Google ничего не отправляется. См. [Сеть и транспорт](../network.md).
