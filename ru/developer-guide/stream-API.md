# Stream API {#stream-api}

Каждый маршрут Warpnet — это протокол libp2p, а каждый вызов — один запрос и один ответ в отдельном потоке. На этой странице показано, как клиент или другой узел делает такой вызов: что нужно для подключения, как запрос оформляется и подписывается, что приходит в ответ и как выглядят ошибки. Страница предназначена для разработчиков, которые пишут узел, бота или клиент на другом языке. Список маршрутов — в [справочнике API](api.md), устройство протокола — в разделе [Протокол](../protocol.md).

## Что нужно для подключения {#what-you-need-to-connect}

Узел Warpnet принимает только соединения, которые используют в точности его стек libp2p. Клиенту нужны:

| Элемент | Значение | Зачем |
|---|---|---|
| Идентичность | Пара ключей Ed25519; peer ID выводится из открытого ключа | Узел проверяет каждый запрос по ключу из вашего peer ID |
| Транспорт | TCP, обернутый в TLS, как в [libp2p-camouflage-transport](https://github.com/Warp-net/libp2p-camouflage-transport) | Узлы слушают только через него; обычное TCP-подключение libp2p не пройдет |
| Ключ частной сети | `SHA-256(network + major version)`, например `SHA-256("warpnet0")`; его выводит `--node.print-psk` | Без него соединение сразу обрывается |
| Защита канала | Noise | Единственный протокол защиты, который предлагает узел |
| Мультиплексор | yamux | Единственный мультиплексор, который предлагает узел |
| Адрес узла | Multiaddr с peer ID узла, например `/ip4/203.0.113.5/tcp/4001/p2p/12D3KooW...` | Из QR-кода сопряжения, стартового лога узла или `/public/get/info` |

Go-реализация всего этого — в [`core/warpnet/options.go`](https://github.com/Warp-net/warpnet/blob/main/core/warpnet/options.go). Компактный пример клиента — хост приложения для Android, который только устанавливает исходящие соединения: [`warpdroid/node/node.go`](https://github.com/Warp-net/warpnet/blob/main/warpdroid/node/node.go). Подробности о каждом слое — в разделе [Сеть](../network.md#the-connection-stack).

Ваши часы должны расходиться с часами узла не больше чем на 5 минут, иначе каждый запрос будет отклонен как устаревший.

## Фрейминг {#framing}

Один поток несет ровно один вызов:

1. Откройте поток к узлу с маршрутом в качестве ID протокола, например `/public/get/info/0.0.0`.
2. Запишите конверт запроса как один JSON-документ.
3. Закройте поток на запись (half-close). Конец потока — единственный разделитель: нет ни префикса длины, ни разделения по переводу строки.
4. Читайте до конца потока. Весь ответ — один JSON-документ.
5. Закройте поток.

Не отправляйте второй запрос в тот же поток — откройте новый. Узел закрывает поток после того, как записал ответ.

## Конверт запроса {#the-request-envelope}

```json
{
  "body": {},
  "message_id": "01JD7Q3K8V6N2M4P5R7S9T0W1X",
  "node_id": "12D3KooWClient...",
  "path": "/public/get/info/0.0.0",
  "timestamp": "2026-11-24T10:15:30.123456789Z",
  "version": "0.0.0",
  "signature": "Base64Signature..."
}
```

| Поле | Обязательное | Примечания |
|---|---|---|
| `body` | да | Тип запроса маршрута из [справочника API](api.md) в виде JSON. Для маршрутов без входных данных используйте `{}` |
| `message_id` | да | Уникален для каждого запроса. Используйте его повторно, только когда повторяете тот же запрос: на маршрутах `post` узел тогда отвечает из кэша идемпотентности и не запускает обработчик снова |
| `node_id` | нет | Ваш peer ID. Узел аутентифицирует вас по соединению, а не по этому полю |
| `path` | да | Маршрут, совпадающий с ID протокола потока |
| `timestamp` | да | RFC 3339, рекомендуется UTC. Должна расходиться с часами узла не больше чем на 5 минут |
| `version` | нет | `0.0.0` |
| `signature` | да | См. ниже |

Тип — `event.Message` в [`event/event.go`](https://github.com/Warp-net/warpnet/blob/main/event/event.go). Кодировка — обычный JSON в UTF-8 с именами полей в snake_case; бинарные медиа передаются в base64 внутри JSON-строк.

### Подпись {#signing}

Подпишите эти байты своим закрытым ключом Ed25519 и поместите результат в base64 (стандартный алфавит) в `signature`:

```text
exact bytes of the "body" value  ||  timestamp as decimal Unix nanoseconds  ||  path
```

Подписывайте байты тела ровно в том виде, в каком записываете их в конверт. Узел проверяет сырой JSON `body` побайтно, поэтому повторное кодирование после подписи (с другими пробелами или порядком ключей) ломает подпись. Подписанная временная метка должна совпадать с отправленной с точностью до наносекунды.

## Пример на Go {#example-in-go}

Вот что узел делает при каждом исходящем вызове ([`core/stream/stream.go`](https://github.com/Warp-net/warpnet/blob/main/core/stream/stream.go)), в сокращенном виде:

```go
body, _ := json.Marshal(event.GetUserEvent{UserId: userId})

msg := event.Message{
    Body:        body,
    MessageId:   ulid.Make().String(),
    NodeId:      host.ID().String(),
    Destination: event.PUBLIC_GET_USER, // serialized as "path"
    Timestamp:   time.Now().UTC(),
    Version:     "0.0.0",
}
msg.Signature = security.Sign(privKey, msg.SigningBytes())
data, _ := json.Marshal(msg)

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
s, err := host.NewStream(ctx, nodePeerID, protocol.ID(event.PUBLIC_GET_USER))
if err != nil {
    return err
}
defer s.Close()

_, _ = s.Write(data)
_ = s.CloseWrite()

_ = s.SetReadDeadline(time.Now().Add(2 * time.Minute))
resp, err := io.ReadAll(s) // a domain.User, or an error object
```

## Пример передаваемых данных {#example-on-the-wire}

Запрос к `/public/get/info/0.0.0`:

```json
{"body":{},"message_id":"01JD7Q3K8V6N2M4P5R7S9T0W1X","node_id":"12D3KooWClient...","path":"/public/get/info/0.0.0","timestamp":"2026-11-24T10:15:30.123456789Z","version":"0.0.0","signature":"..."}
```

Ответ (`warpnet.NodeInfo`) в сокращении:

```json
{
  "type": "member",
  "owner_id": "a1b2c3...",
  "node_id": "12D3KooWNode...",
  "aliases": null,
  "version": "0.8.124",
  "addresses": ["/ip4/203.0.113.5/tcp/4001", "/ip6/2001:db8::5/tcp/4001"],
  "start_time": "2026-11-24T09:00:00Z",
  "relay_state": "waiting",
  "bootstrap_peers": null,
  "reachability": 1,
  "protocols": ["/public/get/info/0.0.0", "/public/get/user/0.0.0", "..."],
  "network": "warpnet"
}
```

`type` принимает значения `member`, `relay` или `moderator`. `reachability` — значение из libp2p: 0 — неизвестно, 1 — публичный, 2 — приватный. `relay_state` становится `running`, когда узел начинает анонсировать relay-адреса (`/p2p-circuit`).

Ответ — это голый тип результата маршрута: он не обернут в конверт и не подписан. Его целостность обеспечивает канал Noise до пира, к которому вы подключились.

## Ошибки {#errors}

Неудачный вызов возвращает объект ошибки вместо типа результата:

```json
{"code":5000,"message":"middleware: auth: stale or replayed message"}
```

| Код | Значение |
|---|---|
| `0` с сообщением `Accepted` | Успех для маршрутов, которые больше ничего не возвращают |
| `5000` | Обработчик завершился с ошибкой (сообщение — это ошибка обработчика), либо middleware аутентификации отклонил запрос: `middleware: internal node error` — если конверт не удалось разобрать, нет `message_id` или подписи либо подпись неверна; `middleware: auth: stale or replayed message` — если временная метка вне допустимого окна; `middleware: auth: unknown client peer` — для приватного маршрута без сопряжения |
| `5001` | Превышен лимит частоты запросов для этого маршрута; повторите позже |
| `0` с другим сообщением | Узел не смог прочитать запрос (`middleware: stream: reading failed`), завершает работу (`node is offline`) или обработчик ничего не вернул (`empty response`) |

Если запрос больше лимита маршрута (1 MiB для большинства маршрутов, 50 MiB для загрузки медиа), узел сбрасывает поток без всякого ответа. Практичная проверка на стороне клиента: если ответ разбирается как `{code, message}` с непустым сообщением, отличным от `Accepted`, считайте его ошибкой. Полная таблица и лимиты размера — в разделе [Протокол](../protocol.md#errors-and-responses).

## Публичные и приватные маршруты {#public-and-private-routes}

Маршруты `public` может вызывать любой пир. Обработчики, которые действуют от имени пользователя, проверяют, что пользователь принадлежит узлу на другом конце потока. Поэтому действовать вы можете только от имени идентичности собственного узла.

Маршруты `private` работают с данными владельца. Узел обслуживает их только для себя и подключенных устройств. Чтобы стать подключенным устройством:

1. Получите токен сессии узла. Desktop-приложение и панель управления удаленного узла показывают его в QR-коде сопряжения. QR-код содержит ответ на вход `domain.AuthNodeInfo` (`user_id`, `token`, `psk`, `node_id`, `addresses`, `bootstrap_peers`, `network`) в виде JSON, сжатого gzip и закодированного в Base45.
2. Подключитесь со своей идентичностью и вызовите `/private/post/admin/pair/0.0.0` с этим объектом в качестве `body`.
3. При успехе узел отвечает своими текущими multiaddr-адресами и принимает приватные маршруты от вашего peer ID, пока устройство не отключат или узел не перезапустится.

Так работают приложения для Android и iOS ([Мобильные приложения](../user-guide/mobile.md)). Desktop-интерфейс и браузерная панель управления вообще не используют потоки: они работают через внутрипроцессный мост узла или через [WebSocket API](ws-API.md).

## Лимиты и рекомендации {#limits-and-good-practice}

- Держите одно соединение на узел и открывайте новый поток на каждый вызов: в yamux потоки дешевы.
- Соблюдайте лимиты частоты: по умолчанию 60 запросов всплеском (burst) и 300 в минуту для чтения, 30 и 120 для записи, меньше для загрузок и сопряжения ([Протокол](../protocol.md#middleware-chain)).
- Если ответ потерялся, повторите запрос с тем же `message_id`, новой временной меткой и новой подписью. Кэш идемпотентности узла хранит результаты 10 минут по ключу из маршрута, пира и `message_id`, поэтому маршрут `post` не выполнится дважды.
- Ждите ответа до 2 минут, для видео — дольше. Сам узел прекращает чтение запроса через 15 секунд (через 5 минут на маршрутах загрузки).
- Будьте готовы к соединениям через relay: если узел за NAT, вы можете попасть к нему через relay-канал (circuit relay), а там действуют лимиты relay на соединение — 1 час и 1 GiB.
