# Stream API {#stream-api}

Каждый маршрут Warpnet — это протокол libp2p, а каждый вызов — один запрос и один ответ в собственном потоке. На этой странице показано, как клиент или другой узел выполняет такой вызов: что нужно для подключения, как запрос разбивается на фреймы и подписывается, что возвращается, как выглядят ошибки и как устройство получает доступ к приватным маршрутам. Страница предназначена для разработчиков, которые пишут узел, бота или клиент на другом языке. Список маршрутов — в [справочнике API](api.md), устройство протокола — в разделе [Протокол](../protocol.md).

## Что нужно для подключения {#what-you-need-to-connect}

Узел Warpnet принимает только соединения, которые используют в точности его стек libp2p. Клиенту нужны:

| Элемент | Значение | Зачем |
|---|---|---|
| Идентичность | Пара ключей Ed25519; peer ID выводится из открытого ключа | Узел проверяет каждый запрос по ключу из вашего peer ID |
| Транспорт | TCP внутри TLS-туннеля, как в [libp2p-camouflage-transport](https://github.com/Warp-net/libp2p-camouflage-transport) | Это единственный транспорт, который слушают узлы; обычное TCP-подключение libp2p не пройдет |
| Ключ частной сети | `SHA-256(имя сети + major-версия)`, например `SHA-256("warpnet0")` для релизов 0.x в основной сети или `SHA-256("testnet0")` в testnet | Без него соединение сразу обрывается. Бинарник relay-узла выводит его с флагом `--node.print-psk`; сопряженный телефон получает его в hex в поле `psk` данных сопряжения |
| Защита канала | Noise | Единственный протокол защиты, который предлагает узел |
| Мультиплексор | yamux | Единственный мультиплексор, который предлагает узел |
| Адрес узла | Multiaddr с peer ID узла, например `/ip4/203.0.113.5/tcp/4001/p2p/12D3KooW...` | Из данных сопряжения, стартового лога узла (`NODE STARTED WITH ID ... AND ADDRESSES ...`) или `/public/get/info` |

Go-реализация всего этого — в [`core/warpnet/options.go`](https://github.com/Warp-net/warpnet/blob/main/core/warpnet/options.go) и [`core/node/node.go`](https://github.com/Warp-net/warpnet/blob/main/core/node/node.go). Компактный пример клиента — хост мобильных приложений, который только устанавливает исходящие соединения: [`warpdroid/node/node.go`](https://github.com/Warp-net/warpnet/blob/main/warpdroid/node/node.go). Подробности о каждом слое — в разделе [Сеть](../network.md#the-connection-stack).

Ваши часы должны расходиться с часами узла не больше чем на 5 минут, иначе каждый запрос будет отклонен как устаревший.

## Фрейминг {#framing}

Один поток несет ровно один вызов:

1. Откройте поток к узлу с маршрутом в качестве ID протокола, например `/public/get/info/0.0.0`.
2. Запишите конверт запроса как один JSON-документ.
3. Закройте поток на запись (half-close). Конец потока — единственный разделитель: нет ни префикса длины, ни разделения по переводу строки.
4. Читайте до конца потока. Весь ответ — один JSON-документ.
5. Закройте поток.

Не отправляйте второй запрос в тот же поток — откройте новый. Узел закрывает поток после того, как записал ответ.

Если узел доступен только через relay-канал (circuit relay), соединение с ним ограниченное, и libp2p не открывает на нем потоки, если контекст потока этого не разрешает. В Go оберните контекст в `network.WithAllowLimitedConn`, как это делают узел и мобильные приложения.

## Конверт запроса {#the-request-envelope}

```json
{
  "body": {},
  "message_id": "01JD7Q3K8V6N2M4P5R7S9T0W1X",
  "node_id": "12D3KooWClient...",
  "path": "/public/get/info/0.0.0",
  "timestamp": "2026-11-24T10:15:30.123456789Z",
  "version": "0.0.0",
  "signature": "Base64Signature..."
}
```

| Поле | Обязательно | Примечания |
|---|---|---|
| `body` | да | Тип запроса маршрута из [справочника API](api.md) в виде JSON. Для маршрутов без входных данных используйте `{}` |
| `message_id` | да | Уникален для каждого запроса. На маршрутах с `/post/` в пути это ключ идемпотентности: используйте его повторно только при повторной отправке того же запроса |
| `node_id` | нет | Ваш peer ID. Узел аутентифицирует вас по соединению, а не по этому полю |
| `path` | да | Маршрут, совпадающий с ID протокола потока; он входит в подписываемые байты |
| `timestamp` | да | RFC 3339, рекомендуется UTC. Должна отличаться от часов узла не больше чем на 5 минут |
| `version` | нет | Узлы отправляют `0.0.0`; поле не проверяется |
| `signature` | да | См. ниже |

Тип — `event.Message` в [`event/event.go`](https://github.com/Warp-net/warpnet/blob/main/event/event.go). Кодировка — обычный JSON в UTF-8 с именами полей в snake_case; бинарные медиаданные передаются в base64 внутри JSON-строк.

### Подпись {#signing}

Подпишите эти байты своим закрытым ключом Ed25519 и поместите результат в base64 (стандартный алфавит) в поле `signature`:

```text
точные байты значения "body"  ||  временная метка в десятичных наносекундах Unix  ||  path
```

Узел проверяет подпись по открытому ключу из peer ID соединения. Подписывайте байты тела ровно в том виде, в каком записываете их в конверт: узел проверяет сырой JSON поля `body` байт в байт, поэтому повторное кодирование после подписи (изменение пробелов или порядка ключей) ломает подпись. Подписанная временная метка должна совпадать с отправленной с точностью до наносекунды.

## Пример на Go {#example-in-go}

Так узел выполняет каждый исходящий вызов ([`core/stream/stream.go`](https://github.com/Warp-net/warpnet/blob/main/core/stream/stream.go)), если оставить только главное:

```go
body, _ := json.Marshal(event.GetUserEvent{UserId: userId})

msg := event.Message{
    Body:        body,
    MessageId:   ulid.Make().String(),
    NodeId:      host.ID().String(),
    Destination: event.PUBLIC_GET_USER, // сериализуется как "path"
    Timestamp:   time.Now().UTC(),
    Version:     "0.0.0",
}
msg.Signature = security.Sign(privKey, msg.SigningBytes())
data, _ := json.Marshal(msg)

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
ctx = network.WithAllowLimitedConn(ctx, "warpnet") // разрешить соединение через relay
s, err := host.NewStream(ctx, nodePeerID, protocol.ID(event.PUBLIC_GET_USER))
if err != nil {
    return err
}
defer s.Close()

_, _ = s.Write(data)
_ = s.CloseWrite()

_ = s.SetReadDeadline(time.Now().Add(2 * time.Minute))
resp, err := io.ReadAll(s) // domain.User или объект ошибки
```

## Пример передаваемых данных {#example-on-the-wire}

Запрос к `/public/get/info/0.0.0`:

```json
{"body":{},"message_id":"01JD7Q3K8V6N2M4P5R7S9T0W1X","node_id":"12D3KooWClient...","path":"/public/get/info/0.0.0","timestamp":"2026-11-24T10:15:30.123456789Z","version":"0.0.0","signature":"..."}
```

Ответ (`warpnet.NodeInfo`), в сокращенном виде:

```json
{
  "type": "member",
  "owner_id": "01JD7Q...",
  "node_id": "12D3KooWNode...",
  "aliases": null,
  "version": "0.8.124",
  "addresses": ["/ip4/203.0.113.5/tcp/4001", "/ip6/2001:db8::5/tcp/4001"],
  "start_time": "2026-11-24T09:00:00Z",
  "relay_state": "waiting",
  "bootstrap_peers": null,
  "reachability": 1,
  "protocols": ["/public/get/info/0.0.0", "/public/get/user/0.0.0", "..."],
  "network": "warpnet"
}
```

`type` принимает значения `member`, `relay` или `moderator`. `aliases` — peer ID подключенных устройств. `reachability` — значение из libp2p: 0 — неизвестно, 1 — публичный, 2 — приватный. `relay_state` становится `running`, как только у узла появляется relay-адрес (`/p2p-circuit`).

Ответ — это просто тип результата маршрута, без конверта и без подписи. Его целостность обеспечивает канал Noise до пира, к которому вы подключились.

## Ошибки {#errors}

При неудачном вызове вместо типа результата возвращается объект ошибки:

```json
{"code":5000,"message":"middleware: auth: stale or replayed message"}
```

| Код | Значение |
|---|---|
| `0` с сообщением `Accepted` | Успех для маршрутов, которые больше ничего не возвращают |
| `5000` | Обработчик завершился с ошибкой (сообщение — это ошибка обработчика), либо middleware аутентификации отклонил запрос: `middleware: internal node error` — если конверт не удалось разобрать, нет `message_id` или подписи либо подпись неверна; `middleware: auth: stale or replayed message` — если временная метка вне допустимого окна; `middleware: auth: unknown client peer` — для приватного маршрута от пира, который не сопряжен с узлом |
| `5001` | `middleware: too many requests for this route`: лимит частоты для этого маршрута исчерпан; повторите позже |
| `0` с другим сообщением | Узел не смог прочитать запрос (`middleware: stream: reading failed`), завершает работу (`node is offline`) или обработчик ничего не вернул (`empty response`) |

Запрос больше лимита маршрута остается без ответа: узел сбрасывает поток. Практичная проверка на стороне клиента: если ответ разбирается как `{code, message}` с ненулевым кодом или с кодом 0 и сообщением, отличным от `Accepted`, считайте его ошибкой.

## Публичные и приватные маршруты {#public-and-private-routes}

Middleware аутентификации ([`core/middleware/auth.go`](https://github.com/Warp-net/warpnet/blob/main/core/middleware/auth.go)) пропускает запрос, если его подпись верна и:

- маршрут `public` — от любого пира;
- маршрут `private`, а вызывающий — сам узел (локальный вызов) или одно из подключенных к нему устройств;
- маршрут — `/private/post/admin/pair`, от любого пира.

Обработчики, которые действуют от имени пользователя, проверяют, что пир на другом конце потока — это узел этого пользователя, поэтому пир может действовать только от имени собственной идентичности. Подключенное устройство считается тем member-узлом, с которым оно сопряжено: оно может вызывать публичные маршруты своего узла от имени владельца, например чтобы ответить на пост или поставить реакцию.

### Сопряжение устройства {#pairing-a-device}

1. Получите данные сопряжения узла — ответ на вход `domain.AuthNodeInfo` (`user_id`, `token`, `psk`, `node_id`, `addresses`, `bootstrap_peers`, `network`). Desktop-приложение и браузерная панель управления показывают их в пункте «Sign in by QR-code» как QR-код (JSON, сжатый gzip и закодированный в Base45); кнопка «Copy connection data» в том же окне выдает обычный JSON.
2. Запустите хост libp2p со своим ключом Ed25519 и PSK из `psk` (hex) и подключитесь к одному из адресов `addresses`, дописав `/p2p/<node_id>`, чтобы рукопожатие Noise подтвердило идентичность узла.
3. Вызовите `/private/post/admin/pair/0.0.0` с этим JSON в качестве `body`.
4. При успехе узел отвечает JSON-массивом своих текущих multiaddr-адресов и сохраняет ваш peer ID как подключенное устройство. Ошибки приходят как объекты ошибки с кодом 5000, например `token mismatch`, `pairing revoked` или `too many aliases`.

Сопряжение действует 72 часа с последнего успешного запроса сопряжения; повторная отправка того же запроса продлевает его и возвращает актуальные адреса. Узел хранит не больше 10 подключенных устройств. Сопряжение заканчивается раньше, если владелец удалит устройство или если member-узел запустится заново: каждый запуск отключает все устройства, а в desktop-приложении узел запускается при каждом входе (удаленный узел — при первом входе в своем процессе). Отключенное устройство не может снова пройти сопряжение с тем же токеном (`pairing revoked`). Токен меняется только при перезапуске процесса узла, поэтому устройству нужны данные сопряжения, полученные после такого перезапуска. Правила для устройств со стороны клиентов описаны в разделе [Клиенты](clients.md#pairing).

Так работают приложения для Android и iOS ([Мобильные приложения](../user-guide/mobile.md)). Desktop-интерфейс и браузерная панель управления не открывают соединений libp2p: они попадают к тем же обработчикам через внутрипроцессный локальный поток, см. [Клиенты](clients.md).

## Лимиты и рекомендации {#limits-and-good-practice}

- Держите одно соединение на узел и открывайте новый поток на каждый вызов: в yamux потоки дешевы.
- Размер запроса: 50 MiB для `/private/post/image`, `/private/post/video`, `/private/post/import/twitter/tweet` и `/private/get/sponsored/buyer`; 1 MiB для всех остальных маршрутов, включая загрузки в чаты. Узел читает запрос не дольше 15 секунд, на маршрутах с лимитом 50 MiB — не дольше 5 минут.
- Лимиты частоты считаются для каждой пары «пир — маршрут» ([`core/ratelimit/stream.go`](https://github.com/Warp-net/warpnet/blob/main/core/ratelimit/stream.go)). По умолчанию маршруты `get` допускают всплеск (burst) 60 и 300 запросов в минуту, остальные маршруты — 30 и 120; владелец может изменить оба значения в настройках лимитов частоты. У некоторых маршрутов свой бюджет: загрузка медиа с узла — 150 и 600, загрузка медиа на узел — 10 и 30, доставка постов в ленту и результатов модерации — 200 и 1200, создание чатов и сообщения — 60 и 300, жалобы — 10 и 30, сопряжение — 5 и 15. Пир с низким [рейтингом](../rating.md) получает только часть бюджета. Маршруты получения видео, кроме того, принимают не больше 2 одновременных потоков от одного пира.
- Если ответ потерялся, повторите запрос с тем же `message_id`, новой временной меткой и новой подписью. На маршрутах с `/post/` узел хранит успешные ответы 10 минут по ключу из маршрута, пира и `message_id` и отвечает на повтор из этого кэша, не запуская обработчик снова. Ответы с ошибкой и ответы больше 64 KiB не кэшируются.
- Узлы ждут ответа до 2 минут; обработчик, которому нужно обратиться к другому узлу, может работать столько же.
- Будьте готовы к соединениям через relay: если узел за NAT, вы можете попасть к нему через relay-канал (circuit relay). Relay, который работает на узле Warpnet, ограничивает каждое соединение через него 1 часом и 1 GiB.
